# DeepLeafAnalyzer

**A Hybrid Deep Learning Framework for ROI-Optimized Multi-Scale Leaf Disease Detection**

## Overview

DeepLeafAnalyzer is a reproducible PyTorch implementation of the research framework “DeepLeafAnalyzer: A Hybrid Deep Learning Framework for ROI-Optimized Multi-Scale Leaf Disease Detection.”

The framework is designed for robust and interpretable plant leaf disease recognition under both controlled and field-oriented imaging conditions. It combines dual-stage Region of Interest (ROI) optimisation, multi-scale feature learning, attention-based refinement, and contextual feature-sequence modelling within a unified deep learning architecture.

Conventional leaf disease classifiers frequently operate on complete images and may therefore learn irrelevant background information, particularly under real agricultural conditions containing illumination variation, clutter, occlusion, scale changes, and complex backgrounds.

DeepLeafAnalyzer addresses these limitations through the following processing pipeline:

```text
Leaf Image
    │
    ▼
Image Preprocessing
    │
    ▼
Dual-Stage ROI Optimisation
    │
    ├── U-Net Segmentation
    └── YOLO-Based Localisation
    │
    ▼
Optimised Disease ROI
    │
    ▼
CNN Feature Extraction
    │
    ▼
Feature Pyramid Network (FPN)
    │
    ▼
Atrous Spatial Pyramid Pooling (ASPP)
    │
    ▼
ViT-Style Self-Attention
    │
    ▼
Channel-Spatial Attention Module (CSAM)
    │
    ▼
Ordered Spatial Feature Sequence
    │
    ▼
LSTM Feature-Sequence Encoder
    │
    ▼
Fully Connected Classification Head
    │
    ▼
Disease Class + Prediction Confidence
```

The implementation is modular so that individual components can be trained, evaluated, replaced, or disabled for ablation experiments.

## Scientific Interpretation

### LSTM Feature-Sequence Encoding

The LSTM is not used to model chronological disease progression. The datasets considered by the proposed framework predominantly contain static leaf images.

Therefore, CNN-generated spatial or multi-scale representations are reorganised into ordered feature sequences and supplied to the LSTM.

For a feature map of shape:

```text
B × C × H × W
```

The spatial representation is rearranged as:

```text
B × (H × W) × C
```

Each spatial feature position functions as one sequence element. The LSTM therefore captures contextual relationships between distributed disease-related features rather than temporal relationships between longitudinal images.

### Confidence Versus Disease Severity

The softmax probability generated by the classification network represents model confidence. It should not be interpreted as a direct biological measurement of disease severity.

Where lesion masks are available, lesion-area coverage can be estimated separately, but this quantity should remain distinct from prediction confidence.

## Leakage-Free Dataset Splitting

The train, validation, and test sets must be generated before stochastic augmentation.

Recommended split:

- Training: 80%
- Validation: 10%
- Testing: 10%

Run:

```bash
python -m src.data.split_dataset \
  --manifest data/manifest.csv \
  --outdir data/splits
```

This generates:

```text
data/splits/
├── train.csv
├── val.csv
└── test.csv
```

Augmentation must subsequently be applied only to the training partition. Validation and test images should receive deterministic preprocessing only.

## ROI Optimisation

DeepLeafAnalyzer uses two complementary localisation mechanisms.

### U-Net Segmentation

U-Net produces a pixel-level disease probability map. A threshold can be used to obtain a binary disease-region mask.

Typical segmentation metrics include:

- Dice coefficient
- Intersection-over-Union
- Precision
- Recall

### YOLO Localisation

A YOLO-family detector identifies disease-containing bounding regions.

The repository contains a local detector adapter in:

```text
src/roi/yolo_adapter.py
```

The adapter accepts a locally trained Ultralytics-compatible detector checkpoint. No pretrained detector weights are downloaded automatically.

## ROI Annotation Requirements

Complete reproduction of the dual-stage ROI system requires:

1. Pixel-level disease masks
2. Disease-region bounding boxes

A recommended annotation structure is:

```text
data/<dataset>/
│
├── images/
├── masks/
├── labels_yolo/
└── manifest.csv
```

ROI annotations may be prepared using tools such as CVAT, Label Studio, LabelMe, or Roboflow. The resulting annotations should be converted to the directory organisation expected by the training pipeline.

## Train the U-Net Segmentation Model

Example:

```bash
python scripts/train_unet.py \
  --train <segmentation-training-manifest> \
  --val <segmentation-validation-manifest> \
  --root .
```

The U-Net can be trained using a combination of Binary Cross-Entropy and Dice loss for lesion delineation.

## Dual-Stage ROI Fusion

```text
U-Net Lesion Mask
        +
YOLO Disease Bounding Box
        ↓
Refined Disease ROI
```

Safe fallback logic is included to reduce the risk of returning an empty ROI when either localisation stage is uncertain.

The resulting ROI is subsequently resized and passed to `HybridLeafDiseaseNet`.

## HybridLeafDiseaseNet

The primary classifier combines several complementary modules.

### Residual CNN Backbone

Learns hierarchical local texture and structural representations.

### Feature Pyramid Network

Combines information from multiple spatial resolutions to support lesions of different scales.

### Atrous Spatial Pyramid Pooling

Uses parallel dilated convolutions to enlarge the effective receptive field while maintaining spatial information.

### Vision Transformer-Style Self-Attention

Models long-range relationships between spatial disease representations.

### Channel-Spatial Attention Module

Refines features according to channel importance and spatial importance.

### Feature-Sequence LSTM

The refined spatial representation is converted into an ordered feature sequence. The LSTM captures contextual dependencies between these spatial feature vectors.

### Classification Head

The encoded representation is passed through fully connected layers to obtain class logits. Softmax probabilities are calculated during inference to provide class probabilities and prediction confidence.

## Default Training Configuration

| Parameter | Value |
|---|---:|
| Random seed | 42 |
| Input resolution | 224 × 224 |
| Optimizer | Adam |
| Initial learning rate | 1e-4 |
| Batch size | 32 |
| Maximum epochs | 100 |
| Dropout | 0.30 |
| Scheduler | ReduceLROnPlateau |
| Scheduler factor | 0.50 |
| Scheduler patience | 5 |
| Early stopping patience | 10 |
| Weight decay | 1e-4 |

A weight decay of `1e-4` is used as an implementation choice because the numerical L2 weight-decay value was not explicitly specified in the manuscript text.

## Recommended Experimental Workflow

1. Download each agricultural dataset separately.
2. Create a dataset manifest.
3. Perform stratified splitting before augmentation.
4. Prepare pixel-level lesion masks.
5. Prepare disease-region bounding boxes.
6. Train U-Net segmentation.
7. Train or fine-tune the YOLO disease detector.
8. Generate or dynamically extract optimised ROIs.
9. Train `HybridLeafDiseaseNet`.
10. Evaluate the complete model on the untouched test set.
11. Train baseline CNN architectures using identical partitions.
12. Perform component-wise ablation experiments.
13. Conduct robustness and cross-dataset experiments where appropriate.
14. Generate Grad-CAM explanations.
15. Analyse prediction calibration.
16. Compute statistical confidence intervals.
17. Measure computational efficiency.

## Reproducibility

The implementation uses a default random seed of `42`.

Random number generators for Python, NumPy, and PyTorch should be seeded consistently. For experimental comparisons, the same dataset splits should be reused across all models.

Model configurations, checkpoints, and output metrics should be preserved together to ensure traceability.

## CPU and GPU Support

The code can run on CPU for functional verification. CUDA is automatically preferred when an appropriate PyTorch CUDA environment and compatible GPU are available.

For large-scale experiments involving U-Net, YOLO, cross-validation, multiple baselines, and ablations, GPU execution is strongly recommended.
